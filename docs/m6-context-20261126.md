### 2.2 深度数据格式

`RosImageCamera` 的 `CamFrame` 包含 `color`、`depth`、`stamp_ms`、`recv` 和 `depth_stamp_ms`。深度图为对齐到彩色图的 `uint16` 毫米值，0 为无效值。插件以 ROS 时间戳配对彩色和深度，默认容差 `3 ms`，缓存 `45` 帧。

`nero_depth.py` 已定义独立保存结构：

```text
<dataset>/
└── depth/
    ├── front/episode_000123.mkv
    ├── wrist/episode_000123.mkv
    └── depth_info.json
```

使用 FFV1 / `gray16le` 无损视频；每个 episode、每个相机写入一帧对应深度，缺帧以全零无效图补齐，以保持帧号对齐。读取接口返回 `(N, H, W)` 的 `uint16` 毫米数组。

### 2.3 当前限制

- Client 的默认轻量 `fast` 相机实现不带深度；只有 `plugin` 相机实现支持深度订阅。
- Client 当前用于推理观测的主路径仍返回 state + front RGB + wrist RGB；深度虽然能从插件读取，但尚未串入模型请求。
- 因此“ROS 能读深度”与“VLA 模型使用深度”是两件不同的事。

### 3.2 Step Flag 口径

M5 使用 `nero_joint_sb`。训练模型内部增加 Step Flag 辅助输出通道（第 9 个预测通道，索引 8）；服务回给机器人的动作仍是 30 × 8。Step Flag 是边界辅助监督，不是任务成功概率。真实执行中仍要由 Client / Web 的步骤门控与人工确认逻辑共同处理。

### 3.3 推理端深度限制

本次 113 的 `serve_openpi_policy.py` 仍以两张图像 `front`、`wrist` 组织模型输入，并通过 `image_to_pil()` 转成 RGB 图像。没有看到原始 `uint16` 深度张量的请求字段或深度编码分支。不能把该服务描述成已支持 RGB-D。
