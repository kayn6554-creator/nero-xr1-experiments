# NERO × XR-1 采集与 VLA 测试台使用手册

版本：v1.0  
更新日期：2026-11-16  
适用机器：采集机 192.168.1.102、113 推理机、NERO 主从臂与双相机

> 本手册把“恢复现场 → 打开网页 → Check → Dry → Live → 记录结果”串成一条可执行流程。第一次使用请从第 1 节开始；日常现场未重启时，不要重复启动已经运行的驱动、相机或服务。

## 0. 先分清三种网页/服务

| 名称 | 端口 | 用途 |
|---|---:|---|
| NERO VLA 采集与测试台 | 8767 | 采集模式、模型连接、Check、Dry、Live、步骤确认和评测 |
| 报告服务 | 8766 | 给测试台提供状态/记录服务，并提供报告页面 |
| 模型推理服务 | 6709 / 6711 / 6712 / 6713 | 113 推理机上的 M3 / M4 / EF4 / M5 WebSocket 服务 |

采集机上的脚本：

- 测试网页：/home/panhe/nero_vla_web.py
- 报告服务：/home/panhe/nero_report_server.py
- 数据目录：/data/panhe/lerobot_data
- VLA 运行记录默认根目录：/data/panhe/vla_runs
- 评测记录默认根目录：/data/panhe/vla_eval

网页和报告服务不是模型服务。8767 能打开不代表模型服务可用；模型连接正常也不代表相机、从臂或 Live 安全检查通过。

## 1. 安全规则：先读再动

### 1.1 任何 Live 前必须满足

- 实体急停在现场、可立即触达，操作人员明确谁负责急停。
- 从臂周围无人手、无松散线缆；工具、容器和台面固定。
- 只有一个程序控制从臂；不能同时运行 VLA Live、遥操作、定位 Move、回放或录制控制。
- 先做 Check，再做 Dry；Dry 通过不等于物理安全已证明。
- 第一次 Live、第一次 M5 边界闭环必须有人现场监督。
- 不在机械臂运动时重启驱动、相机、模型服务或修改代码。

### 1.2 网页按钮的风险等级

| 操作 | 是否会让机械臂运动 |
|---|---|
| 检查模型连接 | 否，只读 metadata |
| 读从臂状态 / Check | 否 |
| Dry | 否，只推理并记录动作块 |
| 查看动作块 | 否 |
| 手动执行回放 | 是 |
| 主臂对齐、遥操作、从臂回到主臂姿态 | 是 |
| 设置夹爪 | 会动夹爪 |
| Live | 是，模型控制从臂 |
| 本步完成 / 评测 / 记录备注 | 按钮本身不直接发机器人动作；M5 中会更新步骤文件，允许下一轮推理继续 |

实体急停优先。不要把网页“停止当前任务”、关锁或软件急停当成实体急停的替代品。

## 3. 每次测试前：只读恢复现场检查

先 SSH 登录采集机：

~~~bash
ssh panhe@192.168.1.102
~~~

执行只读检查：

~~~bash
echo "========== HOST =========="
uptime

echo "========== TMUX =========="
tmux ls

echo "========== CAN =========="
ip -br link | grep -i can

echo "========== WEB / REPORT / ROS PROCESSES =========="
ps -eo pid,ppid,stat,etime,args | grep -E '[n]ero_vla_web.py|[n]ero_report_server.py|[s]tart_ros_driver|[r]ealsense2_camera|[t]eleop|[n]ero_vla_client.py'

echo "========== PORTS =========="
ss -lntp | grep -E ':(8766|8767)([[:space:]]|$)' || true
~~~

判断原则：

- tmux、驱动、相机、报告服务、网页都在运行：不要重启，继续检查。
- 只有网页 8767 不在：只恢复网页，不动报告服务和机器人驱动。
- 8766 不在：先确认报告服务进程确实退出，再恢复报告服务。
- 驱动或相机不在：先停止任何 Live/录制任务，再按第 4 节恢复。
- 不要因为 SSH 终端关闭就认为后台进程退出；以 PID、端口、tmux 和日志为准。

### 3.1 CAN 主从臂映射

当前已确认的 USB-CAN 序列号：

| 接口 | 序列号 | 设备 |
|---|---|---|
| can0 | 003200404648570920363032 | 从臂 |
| can1 | 0029004B5246571520393733 | 主臂 |

只读核对：

~~~bash
for c in can0 can1; do
    echo "========== $c =========="
    udevadm info --query=property --path="/sys/class/net/$c" |
      grep -E 'ID_SERIAL=|ID_SERIAL_SHORT=|ID_PATH='
done

ip -details link show can0
ip -details link show can1
~~~

接口 UP 只说明接口已启用，不代表主臂正在广播。主臂无数据时可在确认机械臂安全静止后被动监听：

~~~bash
timeout 10s candump -L can1
~~~

若没有帧，比较监听前后的 RX packets；如果不增长，继续检查主臂供电、USB-CAN 适配器和物理连接。2026-11-16 曾出现 can1 显示 UP、序列号映射正确但 10 秒无帧、RX 不增长；重新插拔适配器后恢复。根因没有被确定，因此不要把“拔插”当作唯一固定修复，也不要在机械臂运动时拔线。

### 3.2 断电/整机重启后的恢复原则

完整重启恢复与日常检查不同。只有确认机器确实重启、驱动/相机进程已退出，才按依赖顺序恢复：

1. 核对 can0/can1 USB 序列号和 bitrate；正确后才启用接口。
2. 启动从臂 ROS 驱动，随后立即关控制锁。
3. 读取 arm_status 和关节限位；断电自然下垂后可能出现 arm_status 6 和关节超限。
4. 需要时先检查主臂姿态，再按现场已验证的 align_follower 流程恢复从臂；不要在关节超限时盲目按软件急停。
5. 启动头部、腕部相机，检查画面年龄与时间同步。
6. 最后恢复报告服务 8766 和测试网页 8767。

历史交接手册记录的驱动目录为 /data/kaiz/projects/NERO-arm/IK-test，启动脚本为 start_ros_driver.sh effector_type:=agx_gripper；pyAgxArm 位于 /data/kaiz/projects/NERO-arm/pyAgxArm，ROS 工作空间为 /data/kaiz/projects/NERO-arm/agx_arm_ws。执行前必须确认这些路径在当前机器存在且没有重复进程，不要将旧 tmux 窗口编号当成永久配置。

### 4.3 模型服务

模型服务运行在 113 推理机，不在采集机。网页提示模型连接失败时，先检查 host/port、SSH/网络和 113 对应服务端口；不要在采集机启动模型脚本，也不要因为网页连接失败就重启所有服务。

## 5. 测试台界面：先选“测试”

页面顶部有两个模式：

- **采集**：用于主臂遥操作示范采集，按步骤记录数据。
- **测试**：用于已训练 VLA 模型的 Check、Dry、动作块查看、Live 和结果评测。

本轮 M3/M4/EF4/M5 实验使用“测试”模式。

### 5.1 顶部任务与模型连接

顶部字段：

| 字段 | 填什么 | 说明 |
|---|---|---|
| 任务 | 从任务下拉框选 task | 决定任务描述和四步名称 |
| 模型服务 Host | 模型推理机地址 | 当前 113 为 172.16.11.113 |
| 模型服务 Port | 对应模型端口 | M3 6709、M4 6711、EF4 6712、M5 6713 |
| 检查连接 | 点击 | 只连接模型读取 metadata，不读相机、不动手臂 |

当前第一轮任务：

| 网页任务名称 | 任务键 | 场景 | 任务内容 |
|---|---|---|---|
| 水温测量 | task2 | T0 | 抓取温度计、插入水中测温、放回 |
| pH 检测 | ph | H2 | 抓取 pH 计、入水检测、放回 |
| 红外测容器温度 | ircup | W1 | 抓取红外测温仪、对准容器外壁、放回 |

temp 水位必须沿用训练采集时条件。H2、W1 的工具布局和本轮控制变量以第一轮实验协议为准。

### 5.2 ⓪ 准备初始姿态（会动手臂）

此卡片不是每次都要全部执行。只有初始姿态不合适时才使用。

- **1 主臂对齐到从臂**：主臂会运动到从臂当前姿态，从臂不动。
- **时长 / 从臂最快**：遥操作持续时间和速度上限。
- **2 开始遥操作**：拖动主臂，从臂跟随；主从差超过保护阈值会停止。
- **3 结束遥操作**：停止遥操作并关控制锁。
- **从臂回到主臂姿态**：从臂会运动到主臂当前姿态；默认夹爪 93 mm、速度上限 15°/s。
- **只看计划**：只计算回到主臂姿态的计划，不执行。

所有会动的操作都必须先看确认弹窗并满足现场安全条件。不要为了“让模型从某个位置开始”而重复对齐或遥操作。

### 5.3 ① 准备：状态、Check、夹爪

- **读从臂状态**：读取使能和关节限位。
- **检查 Check**：不连接模型、不执行动作，检查从臂状态、两路相机和请求形状。
- **设置夹爪**：只控制夹爪，单位 mm。默认 93 mm；点击后夹爪会运动。

Check 没通过，不要进入 Live。

### 5.4 ② Dry：模型推理但不动臂

- “采 N 块”：建议首次用 8 块。
- 点击“开始空跑”后，Client 连接当前 host/port，调用模型并保存动作块，但不会执行机器人动作。
- Dry 使用当前步骤文本开关；如果启用 step_prompt，会从 Step 1 开始。
- 查看日志中的指令、推理延迟、两路相机时间差、图像年龄、首帧偏差、动作跳变和夹爪范围。

Dry 重点检查：输出有限值、动作维度正确、首帧不突跳、相机画面新鲜、同步正常。Dry 没有触发动作，不代表这些动作在物理世界一定安全。

### 5.5 ③ 查看动作块 / 手动执行

- 选择一条 Dry 记录，再选择其中一个 chunk。
- “执行前 N 步”决定从该块取前多少步。
- “放慢”决定执行速度倍率。
- 点击“手动执行”会让机械臂运动；执行前会检查当前姿态与记录姿态差异。

这不是常规 Pilot 必需步骤。除非明确需要检查某个动作块，否则不要用它替代 Dry 或 Live。

### 5.6 ④ Live：自动运行

先点击对应模型预设按钮，再核对下面所有参数。不要只改端口而保留其他模型的设置。

#### 当前正式测试预设

| 预设 | Host | Port | Step Prompt | 每块执行 | Slow | 夹爪 |
|---|---|---:|---|---:|---:|---|
| M3 | 172.16.11.113 | 6709 | 开 | 30 | 2.0 | absolute |
| M4 | 172.16.11.113 | 6711 | 开 | 30 | 2.0 | absolute |
| EF4 | 172.16.11.113 | 6712 | 开 | 30 | 2.0 | absolute |
| M5 | 172.16.11.113 | 6713 | 开 | 30 | 2.0 | absolute |

EF 原始基线 6710 当前未运行；在恢复服务前，不要把 EF4 的结果写成 EF/EF4 严格对照。

#### 输入项逐项说明

| 输入项 | 含义 | 本轮建议 |
|---|---|---|
| 模型预设 | 一键填入 Host、Port、变体名、Step Prompt、每块步数、Slow | 选择 M3 / M4 / EF4 / M5 |
| Host / Port | 模型服务地址 | 以预设为准 |
| 每块执行 | 每次推理后实际执行多少个预测帧 | 30 |
| 放慢 Slow | 执行动作的放慢倍数 | 2.0 |
| 变体 Variant | 写入运行记录的模型标识；若与预设同名会校验参数 | M3 / M4 / EF4 / M5 |
| 指令带步骤文本 | 是否发送 Step k/4 文本 | 本轮四个模型均开启 |
| 物品 | 当前工具/物品标签，写入运行元数据 | 按当前任务和场景选择 |
| 场景 | 场景 ID，写入运行元数据 | temp=T0、ph=H2、ircup=W1 |
| 外接相机视频编号 | 关联现场外接录像 | 如 VID_0012；按实际文件名填写 |
| 结束后自动回到主臂姿态 | Live 结束后触发从臂回到主臂姿态 | 首轮建议关闭，避免自动追加运动 |
| 最多 N 块 | 最多执行的推理动作块数 | 按协议设置；默认 40 |
| 最长 N 秒 | 本次运行时间上限 | 按协议设置；默认 600 |

如果 Variant 与某个已保存预设同名，Host、Port、Step Prompt、每块执行、Slow 必须与该预设一致，否则网页会拒绝开跑。点击预设按钮重新套用即可。

启动 Live 前再次确认模型连接状态、Check 结果、初始姿态、场景和工具位置。点击“开始自动运行”后会出现“确认：手臂将运动”弹窗；逐项确认现场安全后才能执行。

### 5.7 ⑤ / ⑥ 运行评测与步骤按钮

Live 运行时：

- **本步完成（N）**：记录当前物理步骤完成，并推进步骤状态。
- **撤销（Z）**：撤销最近一次步骤完成标记；仅在界面允许的时间范围内使用。
- **本步失败（1–4）**：选择失败类型并停止本次运行。
- **备注**：记录夹偏、停滞、碰撞、工具掉落、提前退出等现象。

步骤按钮不是让机械臂运动的控制命令，而是给运行记录标注当前步骤；M5 还会用它更新步骤文件，以允许下一轮推理继续。必须在真实物理步骤完成后才按，不要为了让模型继续而提前按。

### 5.8 M5 专项：Step Flag 边界暂停与人工确认

M5 的工作流程：

1. 模型预测 30 帧关节/夹爪动作，同时预测每帧的 Step Flag。
2. 服务端按默认阈值 0.5、连续 2 帧检测步骤边界。
3. 检测到边界后，边界后的动作不再继续推进，机械臂保持在边界前最后一个有效目标。
4. Client Live 只执行边界前有效动作，然后等待步骤文件变化。
5. 操作者确认当前步骤在物理上确实完成，点击“本步完成”。
6. 网页更新步骤文件；Client 读取新步骤后再发起下一次推理。

注意：

- “停住”是边界控制，不等于任务成功。
- 如果停得明显过早、过晚或在不合理位置触发，不要直接点击下一步强行继续；先停止并记录。
- 如果没有触发边界，不能假定当前步骤已完成。
- Dry 只记录 Flag，不会等待人工确认，也不会驱动机械臂。
- 首轮不要在线修改阈值或连续帧数。

2026-11-16 用户已进行约 1–2 次 M5 测试，观察到每一步结束后机械臂稳定停住，直到按下下一步才继续。该反馈是初步现场观察，尚不能替代正式边界精度评测。

### 5.9 ⑦ 顺序与进度

此卡片用于保存模型变体顺序和统计已完成运行。页面提供 A/B 变体与次数输入以及顺序编辑。

正式实验顺序以仓库第一轮实验协议中的 schedule 为准。不要因为网页有“生成顺序”按钮就直接使用默认顺序；生成后应核对是否符合协议要求的平衡块、任务分组和重复次数。

## 6. 推荐的单次测试 SOP

1. 打开网页，切到“测试”。
2. 选择任务：temp / ph / ircup。
3. 选择模型预设：先 M3，再按计划对照 M4、M5；EF4 先做集成 Pilot。
4. 点击“检查连接”，确认 metadata 和 gripper mode 正确。
5. ① 点击“读从臂状态”，再点击“检查 Check”。
6. 确认两路相机画面正常，场景、水位、工具位置和初始姿态符合协议。
7. ② Dry 8 块，检查日志和动作块；不通过就停止，不进入 Live。
8. 核对 ④ 参数：exec_steps=30、slow=2.0、step_prompt 开、absolute gripper、场景/物品/视频编号正确。
9. 在现场急停可用且运动范围清空时启动 Live。
10. M5 在边界停住后，观察实际任务是否完成；确认后再按“本步完成”。
11. 运行结束后在 ⑤/⑥ 完成步骤评测、失败类型和备注。
12. 保存 run_id、视频编号、模型、checkpoint、场景和偏差说明；不要覆盖旧运行。

## 7. 数据与日志在哪里

- 每次 VLA 运行默认写入 /data/panhe/vla_runs 下的独立运行目录。
- 常见文件：summary.json、chunks.npz、feedback.npz、images/、live_status.json。
- summary.json 记录参数、模型变体、推理块、延迟、步骤、结束原因等。
- chunks.npz 保存状态和预测动作块。
- feedback.npz 保存执行目标与从臂反馈（Live）。
- M5 补丁额外记录 Step Flag、边界索引和暂停/等待/确认状态。
- 评测记录默认写入 /data/panhe/vla_eval；网页可按任务查看运行、逐步成功情况和备注。
- 现场外接录像编号填写在 Live 表单中，确保能和运行记录对应。

运行数据、外接录像、summary、chunks 和服务日志应一起归档。不要只保留成功截图而删除失败运行。

## 8. 常见问题速查

| 现象 | 优先检查 |
|---|---|
| 8767 打不开 | SSH 隧道是否存在；ss 是否监听 8767；网页进程是否存在 |
| 页面显示连不上报告服务 | 8766 是否监听；报告服务进程和日志 |
| 检查连接失败 | Host/Port 是否选对；113 对应服务是否监听；网络是否可达 |
| Check 不通过 | 从臂驱动/使能/限位、两路相机、主从姿态 |
| Dry 图像年龄大或同步差 | 相机驱动和 ROS 话题；先不要 Live |
| Live 提示预设不一致 | 重新点击正确模型预设，不要只改一个字段 |
| M5 不暂停 | 检查是否启用 step_prompt、step 文件是否工作、metadata 中 step_flag 是否 enabled，以及本次动作块是否预测到边界 |
| M5 过早暂停 | 记录 Flag 与视频，不要直接确认下一步；停止并归类为边界误触发 |
| can1 UP 但无主臂数据 | 核对 USB 序列号；被动 candump；比较 RX packets；检查主臂供电和物理连接 |
